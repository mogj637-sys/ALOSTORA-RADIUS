# نقاط البيع والطباعة والمخزون

## القاعدة التجارية المعتمدة

يتم ترحيل الكرت إلى نقطة البيع وتسجيل قيمته التجارية عند تنفيذ عملية الطباعة الأولى، وليس عند أول اتصال للعميل. لذلك لا يشترط أن يكون الكرت قد استُخدم حتى يُسجل على نقطة البيع.

الكروت المجانية تظهر في سجل الطباعة الفني، لكنها لا تُخصص تجارياً لنقطة البيع ولا تنشئ حركة مخزون أو قيمة مالية.

## نقاط البيع

جميع المسارات التالية تتطلب تسجيل دخول مشرف بدور `owner`.

- `GET /api/v1/points-of-sale`: عرض نقاط البيع النشطة.
- `GET /api/v1/points-of-sale?include_inactive=true`: عرض جميع النقاط.
- `POST /api/v1/points-of-sale`: إنشاء نقطة بيع بالحقول `code` و`name`، مع `contact_name` و`phone` الاختياريين.
- `PATCH /api/v1/points-of-sale/{point_id}`: تعديل بيانات النقطة أو تفعيلها وإيقافها.
- `GET /api/v1/points-of-sale/{point_id}/inventory`: ملخص الكروت المخصصة والمستخدمة والموقوفة، القيمة التجارية الإجمالية للكروت المطبوعة، وعدد الكروت المجانية المطبوعة.

## الطباعة

- `GET /api/v1/print-jobs?point_of_sale_id={id}&limit=30`: يعرض سجل عمليات الطباعة للنقطة، دون إرجاع كلمات المرور.
- `POST /api/v1/print-jobs`: ينشئ سجل طباعة وعناصره، ويعيد بيانات الدخول اللازمة لمعاينة وطباعة القسائم.
- يجب إرسال `idempotency_key` فريد للعملية، ومعرّف نقطة البيع، وقائمة معرّفات الكروت.
- الحد الأقصى للعملية الواحدة 5000 كرت، ولا يسمح بتكرار معرّف الكرت في الطلب.
- أول طباعة تجارية لكرت منشأ وغير مخصص تنقل حالته إلى `allocated` وتربطه بنقطة البيع وتنشئ حركة مخزون وسجل حدث.
- لا يمكن تخصيص الكرت نفسه لنقطتي بيع.
- إعادة الطباعة تتطلب أن تكون الطباعة الأصلية مسجلة لنفس نقطة البيع. إعادة الطباعة تنشئ سجلاً فنياً جديداً فقط ولا تكرر حركة المخزون أو القيمة التجارية.
- إعادة إرسال نفس الطلب بنفس مفتاح idempotency ونفس البيانات تعيد نتيجة العملية السابقة. استخدام المفتاح نفسه لطلب مختلف يعيد تعارضاً `409`.
- الكرت المجاني يسجل في عناصر الطباعة ويظهر في عداد الكروت المجانية، لكنه لا يُربط بنقطة البيع ولا ينشئ حركة مالية.
- بيانات الدخول لا تظهر في قائمة الكروت أو سجل الطباعة. تعاد كلمات المرور فقط في استجابة عملية الطباعة للمشرف المصرح، مع ترويسات تمنع تخزين الاستجابة مؤقتاً.
- شاشة نقاط البيع في الواجهة تعرض المعاينة بعد الطباعة، وتتيح إعادة طباعة العمليات السابقة.

## مثال طلب طباعة

```json
{
  "idempotency_key": "print-batch-2026-00001",
  "point_of_sale_id": 1,
  "card_ids": [
    "00000000-0000-0000-0000-000000000001"
  ],
  "template_code": "classic-green",
  "is_reprint": false
}
```

## حدود المرحلة الحالية

هذه المرحلة توفر إدارة نقاط البيع والطباعة ومعاينة القسائم وسجل إعادة الطباعة وملخص القيمة التجارية المخصصة لكل نقطة. لم تُستكمل بعد إدارة التحصيلات النقدية والديون والعمولات والتسويات؛ وهذه وظائف محاسبية مستقلة يجب بناؤها قبل اعتبار المحاسبة التجارية مكتملة. كما أن ربط FreeRADIUS وMikroTik الفعلي ما زال مرحلة لاحقة.
