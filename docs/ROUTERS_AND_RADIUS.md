# سجل راوترات MikroTik والتحضير لـ RADIUS

## إدارة سجل الراوترات

تتطلب جميع المسارات مصادقة مشرف بدور `owner`.

- `GET /api/v1/routers`: عرض الراوترات النشطة.
- `GET /api/v1/routers?include_inactive=true`: عرض جميع الراوترات.
- `POST /api/v1/routers`: تسجيل راوتر جديد.
- `PATCH /api/v1/routers/{router_id}`: تحديث البيانات أو تفعيل/تعطيل الراوتر.

حقول التسجيل:

- `name`: اسم وصفي للراوتر.
- `nas_identifier`: قيمة فريدة يجب أن تطابق هوية NAS التي يرسلها MikroTik إلى RADIUS.
- `management_host` و`api_port`: عنوان ومنفذ إدارة RouterOS.
- `api_username` و`api_secret`: بيانات دخول API اختيارية، ويجب إدخال الاثنين معاً أو تركهما فارغين.
- `radius_secret`: المفتاح المشترك بين الراوتر وخادم RADIUS.
- `routeros_version`: الإصدار المسجل، مثل 6.x أو 7.x.

## حماية الأسرار

- لا تعيد استجابات API كلمات المرور أو النصوص المشفرة.
- تُحفظ بيانات RouterOS API وRADIUS في حقول ciphertext فقط.
- يستخدم تشفير أسرار الراوترات مفتاحاً مستقلاً هو `ROUTER_SECRET_ENCRYPTION_KEY`، منفصلاً عن مفتاح تشفير كلمات مرور الكروت.
- أنشئ المفتاح بواسطة:
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
- احتفظ بنسخة احتياطية آمنة من المفتاح؛ فقدانه يمنع فك تشفير الأسرار المخزنة.
- لا تضع أسرار راوترات حقيقية في Git أو سجلات التطبيق.

## ما لم يُنفذ بعد

تسجيل الراوتر لا يعني أن النظام اتصل به أو غيّر إعداداته. لا تزال الخطوات التالية مطلوبة:

1. تنفيذ عميل RouterOS API مع TLS/قيود الشبكة وإدارة الاتصالات والأخطاء.
2. إعداد FreeRADIUS clients من سجل NAS وتوليد/تحديث إعداداته بأمان.
3. إعداد مصادقة الكروت والتحقق من بيانات الدخول.
4. معالجة Accounting Start وInterim-Update وStop مع مقاومة تكرار الحزم.
5. تطبيق الوقت المتصل، مجموع الرفع والتنزيل، الصلاحية من أول استخدام، واتصال واحد.
6. تنفيذ الفصل وCoA/Disconnect واختبارها على RouterOS v6 وv7.

حتى اكتمال هذه الخطوات واختبارها على أجهزة فعلية، تبقى هذه الوحدة سجلاً إدارياً آمناً للراوترات وليست تكاملاً تشغيلياً مع MikroTik أو FreeRADIUS.
