# تصميم قاعدة البيانات – المرحلة الأولى

## الجداول الأساسية
- `plans`: الباقات وحدود الحجم والوقت والصلاحية والسعر والسرعة.
- `cards`: بيانات الكرت، لقطة الباقة والسعر، وقت أول استخدام، انتهاء الصلاحية، وعدادات الاستهلاك.
- `points_of_sale`: نقاط البيع.
- `print_jobs`: عمليات الطباعة مع مفتاح منع التكرار.
- `pos_inventory_movements`: حركات تخصيص الكروت لنقاط البيع والمرتجعات والتحويلات.
- `routers`: أجهزة MikroTik ومعرف NAS وبيانات الاتصال المشفرة.
- `radius_sessions`: جلسات RADIUS ومؤشرات المحاسبة.
- `card_events`: سجل أحداث الكرت.

## قواعد تمثيل الحدود
- `NULL` يعني أن الحد مفتوح.
- لا يستخدم الرقم صفر للتعبير عن حد غير محدود.
- الحجم يخزن بالبايت.
- الوقت يخزن بالثواني.
- المال يخزن باستخدام NUMERIC بدلاً من floating point.

## دورة الصلاحية والاستخدام
- `first_used_at` يثبت عند أول مصادقة ناجحة فقط.
- `expires_at = first_used_at + validity_period_seconds`.
- انتهاء الصلاحية يستمر أثناء انقطاع العميل.
- `used_seconds` يجمع وقت الجلسات الفعلية فقط.
- الاستهلاك الحجمي هو مجموع عدادات الرفع والتنزيل.

## تخصيص نقطة البيع بالطباعة
عملية الطباعة الموجهة لنقطة بيع يجب أن تكون معاملة ذرية:
1. إنشاء `print_jobs` بمفتاح idempotency فريد.
2. ربط الكروت المحددة بنقطة البيع وتسجيل `allocated_at`.
3. إنشاء حركة لكل كرت في `pos_inventory_movements`.
4. تسجيل حدث تخصيص في `card_events`.
5. عند إعادة إرسال نفس الطلب لا تتكرر الحركات بسبب المفتاح الفريد.
6. إعادة طباعة نسخة من كرت سبق تخصيصه لا تنشئ حركة مخزون جديدة.

## ملاحظات أمنية
- حقول أسرار الراوترات وبيانات اعتماد الكروت تحفظ مشفرة، لكن خدمة التشفير وإدارة مفاتيحها لم تُنفذ بعد.
- لا يجوز إرجاع حقول ciphertext في API العام.
- يجب تنفيذ المصادقة والصلاحيات وسجل التدقيق قبل فتح عمليات الإدارة على شبكة فعلية.
