# الباقات والكروت – API الأولية

جميع المسارات التالية تتطلب رمز JWT لمستخدم يحمل دور `owner`.

## الباقات

### إنشاء باقة
`POST /api/v1/plans`

مثال:

```json
{
  "code": "BASIC-1",
  "name": "الباقة الاقتصادية",
  "price": 100,
  "data_limit_bytes": 1073741824,
  "session_time_limit_seconds": 25200,
  "validity_period_seconds": 604800,
  "speed_profile": "default",
  "description": "1GB و7 ساعات و7 أيام"
}
```

أي حد يترك `null` يكون مفتوحاً. لا تستخدم صفر للتعبير عن الحد المفتوح.

### عرض الباقات
`GET /api/v1/plans`

## الكروت

أنواع تسجيل الدخول:
- `username_only`: اسم مستخدم دون كلمة مرور.
- `same_credentials`: اسم المستخدم وكلمة المرور متطابقان.
- `separate_credentials`: اسم مستخدم وكلمة مرور مختلفان.

أنماط توليد اسم المستخدم:
- `digits`: أرقام فقط.
- `letters`: حروف إنجليزية كبيرة فقط.
- `alphanumeric`: أرقام وحروف إنجليزية كبيرة.

### إنشاء كرت منفرد
`POST /api/v1/cards/single`

```json
{
  "plan_id": 1,
  "username": "12345678",
  "card_type": "same_credentials",
  "is_free": false
}
```

لنوع `separate_credentials` أرسل `password`. للكرت المجاني استخدم `is_free: true`. خيار المجاني متاح للكرت المنفرد فقط.

### إنشاء دفعة
`POST /api/v1/cards/batch`

```json
{
  "plan_id": 1,
  "quantity": 100,
  "card_type": "separate_credentials",
  "generation_mode": "digits",
  "username_length": 8,
  "password_length": 10,
  "prefix": "77"
}
```

الدفعة الحالية تقبل من 1 إلى 5000 كرت. إذا حدث تعارض في أسماء المستخدمين أو فشل الحفظ، لا تحفظ الدفعة جزئياً.

### عرض الكروت
`GET /api/v1/cards?offset=0&limit=50`

يمكن استخدام `status` كمرشح. لا يعيد هذا المسار كلمات المرور أو النص المشفر.

## حماية بيانات الاعتماد
- كلمات مرور الكروت تحفظ مشفرة باستخدام Fernet.
- يجب تعيين `CREDENTIAL_ENCRYPTION_KEY` قبل إنشاء الكروت.
- مفاتيح التشفير لا تحفظ في Git ولا ترسل إلى المتصفح.
- استجابة الإنشاء تعرض كلمة المرور مرة واحدة ليتم حفظها أو طباعتها؛ لا توجد واجهة لاسترجاعها كنص مكشوف.
- خدمة RADIUS لم تُربط بعد بعملية فك التشفير؛ لا تستخدم هذه المرحلة لمصادقة مشتركين حقيقيين.

## تحذير مهم بشأن مفتاح التشفير
يجب الاحتفاظ بنسخة احتياطية آمنة من `CREDENTIAL_ENCRYPTION_KEY` خارج الجهاز والمستودع. فقدان المفتاح يعني تعذر فك تشفير كلمات مرور الكروت المخزنة، وتغيير المفتاح دون خطة ترحيل سيؤثر على بيانات الاعتماد الحالية. لا ترسل هذا المفتاح في المحادثة ولا ترفعه إلى GitHub.
